# Contributing
Thank you for taking the time to contribute to the project!

This is primarily a personal project, so I’m not actively looking for direct contributors or maintainers. That said, community involvement is always appreciated in the form of:

- Feature requests
- Suggestions and feedback
- Bug reports
- Optimization ideas
- General code review comments
- Forks and experimental improvements

## Before Opening an Issue

Please check existing issues first to avoid duplicates.

When opening an issue, try to include:

- A clear description of the problem or suggestion
- Steps to reproduce (if applicable)
- Expected vs actual behavior
- Relevant screenshots/logs/examples when helpful

## Pull Requests

While I’m not expecting regular external pull requests, thoughtful pull requests are welcome.

A few guidelines:

- Keep changes focused and minimal
- Explain *why* the change is useful
- Match the existing code style where possible
- Avoid large refactors unless discussed first
- Open an issue beforehand for major changes

Not all PRs will be merged, especially if they significantly change the database structure or ETL/ML pipelines.

## Forks

Forks are completely encouraged.

If you build something interesting from this project, feel free to share it through an issue or discussion or mesage me directly and we can collaborate directly.

## Code Style

There’s no strict contribution workflow right now, but consistency matters. Try to:

- Keep code readable
- Prefer simple solutions
- Comment non-obvious logic
- Avoid unnecessary dependencies

## Discussions & Feedback

Constructive feedback is always welcome, whether it’s:

- Performance improvements
- Better architecture ideas
- UX suggestions
- Cleanup opportunities
- Documentation fixes

Even small comments can be helpful.
